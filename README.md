# Avtobus v Italiu

Предпросмотр: https://alexalixmanov-del.github.io/avtobus-v-italiu/
GitHub Pages публикует папку `docs/` из ветки `main`. После изменения исходников
выполните `npm run build:pages` и сохраните обновлённую `docs/` в Git.
Предпросмотр закрыт от индексации; canonical остаётся на домене основного сайта.

Статический сайт с украинской главной `/`, русской `/ru/` и итальянской `/it/`.
Заголовки, тексты, FAQ и SEO находятся в готовом HTML. React подключает выбор
рейса, необязательных мест и заявку к существующему Google Apps Script API.

## Разработка

Нужны Node.js 20+ и npm. Python 3 используется только для локального сервера.

```sh
npm ci --cache /tmp/avtobus-npm-cache
npm run build
npm run serve
```

Сервер слушает порт 8080. Для браузерных проверок:

```sh
# Если системный Chromium отсутствует:
npx playwright install chromium
npm test
```

Тесты используют системный `/usr/bin/chromium`, установленный Playwright Chromium
или путь `BROWSER_PATH`. Проверяются HTML без JavaScript, языковые URL, экраны
320/360/390/430/768/1280 px, мобильный сенсорный режим, изображения и шрифты,
места, поля, конфликт места, ошибка отправки и повторная попытка. Дополнительно
проверяются нормализация телефонов, реальные дни выезда для всех городов,
таймаут 10 секунд, опрос раз в 60 секунд только в активной вкладке и заявка
без места при недоступной схеме. Запросы
бронирования перехватываются тестовым API: настоящие заявки не создаются.
Axe проверяет доступность, включая контраст, на мобильной странице бронирования
и юридических страницах. Это автоматические проверки в Chromium, а не тест
на физических iPhone/Android и не проверка доставки настоящих заявок.

Проверяется сценарий с мобильной нижней кнопкой: неправильный телефон → ошибка
после выхода из поля → нажатие → фокус у ошибки → исправление → отправка.
Обе кнопки отправки используют одну проверку. Ошибки email и согласия видны
рядом с полями. Нижняя панель содержит стоимость и одну кнопку; схема мест
по умолчанию свёрнута, преимущества имеют 3×2 карточки на компьютере.

Незавершённая заявка сохраняется в `sessionStorage` текущей вкладки при
переключении UA/RU/IT, включая маршрут, пассажиров, места и багаж. При
восстановлении доступность мест запрашивается заново. После принятой заявки
черновик удаляется; записи старше 24 часов удаляются при следующем открытии.
Если браузер блокирует хранилище, сама форма продолжает работать.
JavaScript подключается с хэшем в query string, чтобы после установки
обновления телефон загрузил новую версию кода.

## Сборка для хостинга

```sh
SITE_URL=https://your-domain.example npm run build
```

`SITE_URL` — HTTPS-домен без пути. По умолчанию сохранён домен исходного архива:
`https://avtobus-v-italiu.dg-s.space`. Он используется в canonical, Open Graph,
hreflang, Schema.org, sitemap и robots.txt. `SITE_LASTMOD=YYYY-MM-DD` позволяет
указать дату обновления; по умолчанию используется день сборки по времени Киева.

Загружайте **содержимое `dist/`** в корень сайта. Node.js на хостинге не нужен.
Хостинг должен обслуживать `/ru/index.html` и `/it/index.html` как `/ru/` и `/it/`;
правило, возвращающее главную вместо любых путей, для этих страниц не требуется.
Сохраняйте собственные файлы конфигурации и другие данные хостинга. Старый
`support.js` новая сборка не использует.

`robots.txt` разрешает индексацию, включая ИИ-ботов, одной группой `User-agent: *`.
Если хостинг добавляет собственные запреты автоматически, отключите их в настройках
хостинга: файла этого управляемого блока в исходном архиве нет.

## Где править

- `src/home.html` — шаблон интерфейса. Компилируется во время сборки.
- `src/booking.js` — переводы, расписание, цены, состояния и API бронирования.
- `src/head.html`, `src/improvements.css` — оформление.
- `src/oferta.html`, `src/privacy.html` — юридические страницы; условия перевозки
  и реквизиты сохранены. Убрано упоминание удалённого Google Fonts.
- `scripts/build.mjs` — пререндер, сборка клиентского кода и SEO.
- `public/` — готовые WebP и иконки; `src/images/` — исходные изображения.

React и ReactDOM 18.3.1 размещаются на сайте как
`assets/vendor/react.production.min.js` и `react-dom.production.min.js`.
Шрифты размещаются на сайте, четыре начертания: Manrope 500/700 и Unbounded 500/800.
Лицензии включаются в `dist/assets/fonts/`. Логотип для шапки — 5,4 КБ, большой
вариант для подвала — 15,3 КБ. Hero 900/1600 в WebP — 38,8/106,2 КБ.
На телефонах фотография ограничена высотой 300 px, чтобы не растягивать
горизонтальный исходник на всю высокую форму.

В архиве **нет** оригинальной вертикальной фотографии около 800×1600 и фото
реального салона. Их не подменяли выдуманными изображениями. Эти два пункта
требуют исходных фотографий перевозчика.

## Бронирование

Адрес Google Apps Script сохранён в `SHEET_URL` в `src/booking.js`.
Токенов Telegram в клиентском коде нет; уведомления выполняет существующий сервер.
По умолчанию выбрано «Будь-яке — підбере менеджер»: схема вообще не нужна для
отправки заявки. При желании можно открыть схему; запрос ограничен 10 секундами,
опрос выполняется с интервалом не менее 60 секунд и только в активной вкладке.
Ошибка схемы блокирует выбор конкретного места, но **не отправку заявки**.
Устаревшие ответы другого маршрута игнорируются. При ошибке отправки видны
WhatsApp с готовым текстом и телефон. Ссылки WhatsApp/Viber не требуют места;
для Viber рядом есть копирование текста, потому что URI чата не заполняет его
надёжно на всех устройствах.

Телефон очищается до цифр и `+`; украинский локальный номер нормализуется
в `+380…`. Для `+380` требуются 12 цифр, для `+39` — 11–13; остальные номера
должны иметь международный префикс и 9–15 цифр. Ошибка отображается у поля.

Сервер должен принимать `seats: ""` и `seatPreference: "any"` без обязательного
номера места, а для выбранного места — проверять доступность при окончательной
записи. Исходников Google Apps Script в архиве нет: клиентская проверка не
доказывает, что сервер уже принимает необязательные места. Если сервер их
отклоняет, приложение показывает резервный переход в WhatsApp; серверный
валидатор потребуется изменить отдельно.

Селект, лента дат, заголовок рейса, билет, модалка и текст заявки показывают
**фактическую дату посадки из выбранного города**: Рівне/Львів/Стрий/Ужгород —
среда, Trieste/Venezia/Padova/Rovigo в обратном направлении — суббота.
При смене города дата сдвигается с сохранением того же общего рейса.

Для согласованности чтения и записи существующей таблицы внутренний ключ API
`date` сохраняет день старта общего рейса (вторник/пятница). Фактическая дата
передаётся в `departureDate`, `departureDateLabel` и тексте `message`. Если
серверная таблица должна отображать фактическую дату отдельной колонкой,
Google Apps Script должен записывать новые поля. Изменять ключ только в POST,
оставляя GET на старом ключе, нельзя: схема потеряет видимость бронирования.

Точки посадки и высадки хранятся вместе с городами в `UA_CITIES` / `IT_CITIES`
(`src/booking.js`): `points` — один или несколько адресов, `map` — ссылка Google Maps
для точки без текстового адреса. Без них выводится «Точную точку сообщит менеджер»
(сейчас — Стрий, Ужгород, Marotta). Адрес попадает в блоки на странице, текст
заявки и поля `boardingAddress` / `dropoffAddress`.

Цена задаётся полем `tier` итальянского города — это ссылка на колонку тарифа
украинского города (`base`, `pesaro`, `ancona`, `pescara`). Fano, Marotta,
Senigallia и Civitanova используют `tier: 'ancona'` и сохраняют своё название.
Пока у города `arr` / `dep` равны `null`, он доступен как пункт назначения,
время показывается как «уточнюйте», а в направлении Италия → Украина город
появится в списке отправления, как только будет заполнен `dep`.

Код Google Apps Script лежит в `apps-script/Code.gs`, проверка на имитации
таблицы — `npm run test:apps-script`.
Оплата в билете, FAQ и оферте едина: наличными водителю при посадке после
подтверждения менеджером; обещания онлайн-оплаты и возврата на карту удалены.

Первоначально настоящий API был заблокирован сетевым прокси с `403 Forbidden`.
После обновления сетевого доступа повторный GET вернул HTTP 200,
`success: true`, пустой массив мест для проверенного рейса. Нужны разрешённые
назначения `script.google.com` и `script.googleusercontent.com`. Моделируемые сценарии
не подтверждают работу сервера, Telegram и почтовых уведомлений. Порядок
проверки реальными устройствами описан в `MOBILE_ACCEPTANCE.md`.
